# MM-PHATE Reproducibility

Reproducibility code for the paper:

**Multiway Multislice PHATE: Visualizing Hidden Dynamics of RNNs through Training**
Jiancheng Xie, Lou C. Kohler Voinov, Noga Mudrik, Gal Mishne, Adam Charles (2024)
[[arXiv 2406.01969]](https://arxiv.org/abs/2406.01969)

![MM-PHATE animation](har_mmphate_3d_epoch_animation_colored_by_timestep.gif)

MM-PHATE extends **M-PHATE** to RNNs by constructing a multiway multislice graph across
training epochs, within-sequence timesteps, and hidden units — enabling a single 3-D
embedding that captures how internal dynamics evolve through training.

---

## Quick start

Install and reproduce all figures from pre-computed cache in ~minutes (no GPU needed):

    pip install -r requirements/base.txt && pip install -e .
    mmphate-repro reproduce --mode cache

Figures are written to `figures/`.

> **Pre-computed embeddings and training data for Area2Bump and HAR are included in this
> repository** (`results_cache/area2bump/`, `results_cache/har/`, `data/area2bump/`,
> `data/har/`), so cache mode works out of the box after install.

## Reproduce paper figures

### Cache mode — fast (~minutes)

Regenerates figures from pre-computed embeddings. No GPU required.

    mmphate-repro reproduce --mode cache

### Full mode — slow (~hours)

Generates synthetic data, trains all models, computes embeddings, then plots.

    mmphate-repro reproduce --mode full

    # Multi-core (speeds up MM-PHATE embedding significantly)
    mmphate-repro reproduce --mode full --n_jobs 8

`configs/figure_manifest.json` controls which scenarios and run IDs are used.
Edit it to change hyperparameters or scenario selection without touching code.

## Individual dataset commands

### Synthetic suite (Hopf / Pitchfork bifurcations)

    # Generate rnn_traces.npz from ODE simulations
    mmphate-repro synthetic-generate

    # Compute MM-PHATE / PCA / t-SNE embeddings and neighborhood metrics
    mmphate-repro synthetic-suite --root data/synthetic/

    # Generate 2D grid figures from cache
    mmphate-repro synthetic-figures \
      --scenarios hopf_bif__pitchfork_bif__no_warp__seed24 \
                  hopf_bif__pitchfork_bif__warp__seed24 \
                  hopf_bif__clean_vs_warped__seed24

### Area2Bump (primate somatosensory cortex)

    # Option A: import an existing trained run (reuses saved MM-PHATE, recomputes PCA/t-SNE)
    mmphate-repro area2bump-import --run_id paper_run \
      --legacy_dir "path/to/your/existing/run"

    # Option B: train LSTM from scratch, trace activations, compute embeddings, cache
    mmphate-repro area2bump-run --run_id paper_run --epochs 200 --units 20

    # Generate figures from cache
    mmphate-repro area2bump-figures   --run_id paper_run
    mmphate-repro area2bump-figures3d --run_id paper_run

### HAR (Human Activity Recognition / kinematics)

    # Option A: import an existing trained run (reuses saved MM-PHATE, recomputes PCA)
    mmphate-repro har-import --run_id paper_run \
      --legacy_dir "path/to/your/existing/run"

    # Option B: train from scratch
    mmphate-repro har-run --run_id paper_run --epochs 1000 --units 30

    # Generate figures from cache
    mmphate-repro har-figures --run_id paper_run

## Apply MM-PHATE to your own data

You can run MM-PHATE on any RNN without modifying the library.

### Step 1 — Record hidden-state traces during training

`m_phate.train.TraceHistory` is a **Keras callback** (`tf.keras.callbacks.Callback`).
It calls `trace_model(x_trace)` at the end of every epoch and appends the result.

```python
import m_phate.train

# x_trace: a small fixed subset of input sequences held constant for all epochs.
# Shape (S, T, F):  S = number of trace samples (e.g. 5 per class × 8 classes = 40),
#                   T = sequence length (timesteps),
#                   F = input features per timestep.
# Choose a representative subset of your training data once before training.
x_trace = X_train[trace_indices]      # shape (S, T, F)

# trace_model outputs only hidden states, not the classification head.
trace_cb = m_phate.train.TraceHistory(x_trace, trace_model)
model.fit(X_train, y_train, callbacks=[trace_cb])
# trace_cb.trace: list of length E, each entry shape (S, T, H)
#   S = trace samples, T = timesteps (intrinsic steps), H = hidden units
```

> **Non-Keras frameworks**: call `trace_model(x_trace)` manually at the end of each
> epoch and collect results into a list — then proceed from Step 2 the same way.

### Step 2 — Reshape into (ET, H, S) format

```python
import numpy as np
from mmphate_repro.pipelines.trace_standardize import standardize_trace_tensor

raw = np.array(trace_cb.trace)                                                   # (E, S, T, H)
std = standardize_trace_tensor(raw, n_samples=S, n_timesteps=T, n_units=H)      # (E, T, H, S)

# Optionally subsample epochs / timesteps to reduce memory
std_sub = std[epoch_indices][:, timestep_indices]                                # (E_s, T_s, H, S)
E_s, T_s = std_sub.shape[:2]
trace = std_sub.reshape(E_s * T_s, H, S)                                        # (ET, H, S)
```

### Step 3 — Embed

```python
from mmphate_repro.embeddings.runners import embed_mmphate

embedding = embed_mmphate(trace, n_components=3)                   # (ET*H, 3)
# Pass cache_path to skip recomputation on reruns:
embedding = embed_mmphate(trace, n_components=3, cache_path="my_emb.npy")
```

### Step 4 — Build label arrays and plot

```python
ET, H, S = trace.shape
epoch_label    = np.repeat(np.repeat(epoch_indices, T_s), H)
timestep_label = np.repeat(np.tile(timestep_indices, E_s), H)
unit_label     = np.tile(np.arange(H), ET)

import matplotlib.pyplot as plt
xy = embedding[:, :2]
fig, axes = plt.subplots(1, 3, figsize=(12, 4))
for ax, label, title in zip(axes,
                             [epoch_label, timestep_label, unit_label],
                             ["epoch", "timestep", "unit"]):
    ax.scatter(xy[:, 0], xy[:, 1], c=label, s=1, alpha=0.5)
    ax.set_title(title)
    ax.set_xticks([])
    ax.set_yticks([])
plt.tight_layout()
plt.savefig("my_mmphate.png", dpi=150)
```

## Reproducibility notes

- Random seeds are set in all training and embedding scripts.
- t-SNE and some GPU ops may give slightly different results across platforms or library versions.
- For exact reproduction, use the pinned versions in `requirements/`.
